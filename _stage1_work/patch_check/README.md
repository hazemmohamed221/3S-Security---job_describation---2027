# 🛡️ شركة ثري إس للأنظمة الأمنية — منظومة حوكمة بطاقات الوصف الوظيفي (2027)

تطبيق ويب متكامل باللغة العربية مبني باستخدام **Python** و **Streamlit** و **SQLite** لإدارة ومراجعة وتحديث وتدقيق وتوثيق بطاقات الوصف والتوصيف الوظيفي لكافة إدارات وقطاعات الشركة، مع دعم كامل للاتجاه من اليمين إلى اليسار (RTL).

---

## 🌟 الميزات الرئيسية للنظام

### ١. واجهة ومحتوى عربي بالكامل مع دعم (RTL)
- تم تعريب وتنسيق كافة بطاقات الوصف الوظيفي للشركة (٢٦ وظيفة قيادية وإشرافية وتنفيذية).
- محاذاة الجداول والقوائم والنماذج من اليمين إلى اليسار مع خط عربي احترافي (`Cairo`).
- تصدير رسمي إلى ملفات Word (.docx) منسقة باللغة العربية وجاهزة للطباعة والتوقيع.

### ٢. دورة عمل وصلاحيات معتمدة

#### 👔 الدور الأول: مدير الإدارة / الموظف (Role A)
- **استعراض بطاقة الوصف الوظيفي المخصصة**: عرض تفاصيل الوظيفة، الهدف العام، الأبعاد الإشرافية، جدول المسؤوليات ومؤشرات الأداء (KPIs)، الصلاحيات، المؤهلات، والمخاطر.
- **إجراءان مباشران**:
  - **الخيار الأول (اعتماد كما هي)**: تأكيد الموافقة على البطاقة بضغطة زر وتوثيق الاعتماد في سجل النظام.
  - **الخيار الثاني (طلب تعديل بند)**: اختيار البند أو المسؤولية، رؤية النص الحالي، كتابة النص المقترح، وتحديد المبرر الفني للرفع لمدير الموارد البشرية.
- **متابعة طلبات التعديل**: شاشة خاصة لمتابعة حالة الطلبات وردود وقرارات الموارد البشرية.

#### 👑 الدور الثاني: مدير الموارد البشرية / مسؤول النظام (Role B)
- **لوحة مؤشرات قيادية**: إحصائيات الإنجاز والاعتماد وتوزيع البطاقات على الإدارات.
- **مراجعة التعديلات جنباً إلى جنب**:
  - مقارنة بصرية دقيقة بين النص الحالي المعتمد والتعديل المقترح.
  - إبراز الفروقات اللونية (إضافة باللون الأخضر / حذف باللون الأحمر المشطوب).
  - قرار فوري بالقبول أو الرفض مع إضافة توجيهات الموارد البشرية.
- **رفع بطاقات Word جديدة**: واجهة سحب وإفلات لملفات Word (.docx) لتحليلها وإدراجها آلياً في قاعدة البيانات.
- **سجل التعديلات التاريخي (Audit Trail)**: توثيق غير قابل للحذف لكل عملية تعديل أو اعتماد مع التاريخ واسم المستخدم.
- **جدول المقابلات الميدانية**: متابعة جدول المقابلات ومخرجات الاجتماعات مع مديري الإدارات مستخرج من ملف الشركة المعتمد.

## 🔐 التشغيل الآمن وإدارة الحسابات

أُزيلت الحسابات التجريبية من واجهة الدخول والتبديل بين المستخدمين. تسجيل الدخول يتطلب إدخال بيانات الحساب والتحقق منها في قاعدة البيانات. صلاحيات التعديل والاعتماد للمدير والموظف تقتصر على البطاقة المخصصة، مع استمرار استعراض دليل الشركة.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m scripts.migrate_passwords
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python -m streamlit run app.py
```

الترحيل يحفظ كلمات المرور الحالية كقيم Argon2id في العمود الحالي دون تغيير الجداول أو المعرفات أو السجلات التاريخية. يجب تغيير كلمات المرور التي سبق نشرها من خلال أداة إدارة الحسابات، باستخدام إدخال سري تفاعلي:

```powershell
.\.venv\Scripts\python -m scripts.manage_account --username YOUR_USERNAME
```

لا يتم إنشاء حسابات أو كلمات مرور افتراضية في التشغيل الجديد. لإنشاء مسؤول جديد بشكل صريح:

```powershell
.\.venv\Scripts\python -m scripts.manage_account --username YOUR_ADMIN --create-admin
```

تُنشأ نسخة SQLite متسقة ومختبرة الاستعادة قبل بدء عملية الخادم وقبل الترحيل أو تغيير بيانات الحسابات في `data/backups/`. قد تحتوي النسخ السابقة للترحيل على كلمات المرور القديمة؛ يجب حمايتها بصلاحيات نظام التشغيل وعدم نشرها. لا ترفع قاعدة البيانات أو النسخ الاحتياطية أو مستندات الموظفين إلى مستودع عام. التشغيل الإنتاجي يتطلب تخزيناً دائماً ونسخاً محمية خارج الجهاز.
